How LocalLane works

Animated walkthrough of the proxy, routing, HTTPS, the daemon, port forwarding, and the public tunnel. Everything below loops on its own — just watch the dots move.

1 · Host-based routing core

The proxy reads the Host header of each request and forwards it to the matching app. Two domains, one proxy.

request for myapp.test request for blog.test

In code: server.ts does host = req.headers.host, finds the domain in config.yaml, and forwards to 127.0.0.1:<port>. If no domain matches → 404. If the app is down → clean 502.

2 · Path routes & prefix stripping routing

Within one domain, paths can fan out to different apps. The matched prefix is stripped so the upstream sees its own path.

/about → :3000 (unchanged) /api/users → :8080 as /users (prefix stripped)

The bug I fixed: the old code matched the route a second time after stripping, so /api/users became /users, matched nothing, and went to :3000. Now it matches once and reuses that decision.

3 · HTTPS & SNI tls

A local root CA signs a certificate per domain. During the TLS handshake, the browser names the host (SNI) and the proxy serves the matching cert.

① browser says “I want myapp.test” (SNI) ② proxy serves that domain’s cert ③ TLS terminated → same routing as HTTP

Why it’s trusted: you trust the root CA once (ca command). Every per-domain leaf cert is signed by it, so the browser trusts them all. Verified with openssl: issuer=LocalLane Local CA, verify 0 (ok).

4 · Daemon & IPC process

The daemon runs the proxy detached from your terminal and tracks it with a PID file. A Unix socket is a private control channel to talk to it.

start → spawn detached, save PID command over Unix socket reply (uptime, domains…)

Two files do the work: the .pid file lets status/stop find the process; the .sock file is a local-only channel so daemon status can ask the live process for its uptime and domains, and stop can shut it down gracefully.

5 · Port forwarding sockets

Ports 80/443 need root, so the proxy uses 10080/10443. forward is a raw byte pipe that bridges them — so you can drop the port suffix.

same bytes, just moved from a privileged port to an open one

Why it works for HTTPS too: the forwarder copies raw bytes and never parses HTTP, so encrypted TLS passes straight through — it’s decrypted later by the HTTPS proxy.

6 · Public tunnel websocket

Expose localhost to the internet. Your machine dials out to a public server over a WebSocket — no inbound firewall hole needed (the ngrok trick).

request: visitor → server → (WebSocket) → your client → local app response retraces the same path back

The trick: the server can’t reach your laptop directly. So it serializes each HTTP request to JSON (body base64-encoded) and pushes it down the WebSocket your client already opened. The client replays it locally and sends the response back the same way.
